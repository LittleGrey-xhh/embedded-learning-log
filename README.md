## 二、知识点

### 1. ★★★ 16 点阵字库就是"索引表 + 32 字节"

一份字库两个数组：

```c
const char* g_font_dot_matrix_16_index[N];   // 索引表：每个字一个字符串
const char  g_font_dot_matrix_16[N][32];     // 点阵：每个字 32 字节
```

16×16 = 256 个像素，1 bit 一个 = **32 字节**。布局是 SSD1306 的页格式：

```
第 0~15 字节 → 上半 8 行（每字节一列，bit0 是最上面那行）
第 16~31 字节 → 下半 8 行
```

所以显示一个字的代码是"按页写两次，每次 16 列"：

```c
for (i = 0; i < 2; i++) {
    OLED_Set_Pos(x, page + i);
    OLED_WR_Data(&g_font_dot_matrix_16[no][16 * i], 16);
}
```

### 2. ★★ 编号规则：ASCII 的编号 = ASCII 码 − 0x20

索引表从空格开始排，所以：

```
' ' (0x20) → 编号 0
'0' (0x30) → 编号 16
'A' (0x41) → 编号 33
'a' (0x61) → 编号 65
```

ASCII 段之后接全角符号，最后才是汉字。**编号就是数组下标，没有别的玄机。**

### 3. ★★★ 中英文混排靠"宽度累加"，不是等宽

`OLED_ShowString` 一字一字往前走，**汉字推 16 像素，ASCII 推 8 像素**：

```c
if (*p_str > 0x7F) current_x += font_size;      // 汉字 16
else               current_x += font_size / 2;  // ASCII 8
```

判断宽度的依据是 UTF-8 首字节：

| 首字节范围 | 字节数 |
|---|---|
| ≤ 0x7F | 1（ASCII） |
| 0xC2 ~ 0xDF | 2 |
| 0xE0 ~ 0xEF | 3（常用汉字） |
| 0xF0 ~ 0xF7 | 4（emoji） |

查表用的是 `strncmp(索引项, target, 字符字节数)`，**按 UTF-8 字节数比前几个字节**，这样不会把"你"和以同字节开头的别的字搞混。

### 4. ★★★ 图片转 OLED：页格式 + 阈值，两步

1. **二值化**：屏幕只有亮/不亮，必须定一个阈值把灰度切两半
2. **转页格式**：`data[页号 × 宽 + 列号]`，每字节 8 个垂直像素，bit0 在最上面

**反相要特别注意**：OLED 是黑底亮像素，所以"白色的地方"要变成 0（不亮），"黑的地方"才置 1。这个逻辑跟看图片的直觉是反的。

### 5. ★★★ 128×64 单色屏的正确用法是文字，不是图片

两张素材的实测结论：

| 素材类型 | 结果 |
|---|---|
| 彩色插画（浅色系） | 灰度层次全被白底吃掉，只剩几根描边，认不出 |
| 真实照片 | 高阈值剪影能认，但像粗糙的简笔画 |
| **纯黑白线稿 / 像素画** | **唯一可行的图片类型** |

根本原因：**总共只有 8192 个点，还是非黑即白**。彩色图和照片的信息量根本塞不进去。

反过来，16 点阵的文字在这块屏上极其锐利，信息密度高得多。**同一块屏，文字比图片划算一个数量级。**

### 6. ★★★ 全汉字库装不进 64KB，必须裁剪

| 字库规模 | 点阵 | 指针表 | Flash 总占用 |
|---|---|---|---|
| 141 项（2 汉字） | 4.5 KB | 0.6 KB | 约 18 KB（28%） |
| 341 项（200 汉字） | 10.7 KB | 1.3 KB | **约 30 KB（48%）** |
| 1138 项（1000 汉字） | 35.6 KB | 4.4 KB | 约 60 KB（94%） |
| 3891 项（3752 汉字） | 121.6 KB | 15.2 KB | **163 KB（256%）→ 编译报错** |

`L6406E: No space in execution regions` 就是这个，链接器算完发现放不下直接不给生成 axf。

**结论：汉字数量按项目实际要显示的内容挑，不要一次全导。** 保留一份全字库当母本，改字表时重新裁。

### 7. ★★ ARMCC 认 UTF-8 BOM，无 BOM 就当 GBK

| 文件状态 | ARMCC 的反应 |
|---|---|
| UTF-8 **有** BOM（`EF BB BF`） | 正确识别，`"你好"` 这类中文字符串零错误 |
| UTF-8 **无** BOM | 按 GBK 解析，汉字字节被两个两个吃掉，**连结尾的引号一起吞**，报 `#8: missing closing quote` |

所以规则很明确：**含中文字符串的源文件必须带 BOM；不含中文的文件不要带**（shell 脚本、HTML 带 BOM 会出别的问题）。

### 8. ★★ 链接器会静默删掉"没人用"的数据

编译 0 错误但 `RO-data` 只有几百字节，说明字库被当成垃圾删了。查 `Template.map` 能看到：

```
Removing oled.o(i.OLED_ShowString), (126 bytes).
Removing fontdotmatrix16.o(.constdata), (4512 bytes).
```

原因是没有任何代码调用文字显示函数，链接器的 unused section elimination 从 `main` 开始标记可达符号，不可达的全删。

**排查口诀：代码明明写了但没效果 → 先看 map 有没有 Removing。**

### 9. ★ 函数参数的位宽要跟着数据规模走

```c
void OLED_ShowCHinese(uint8_t x, uint8_t y, uint8_t  no, ...)   // 最多 255 个
void OLED_ShowCHinese(uint8_t x, uint8_t y, uint16_t no, ...)   // 改后
```

字库超过 256 项以后，`uint8_t` 的索引会被**静默截断**（第 300 个字会显示成第 44 个），不报错、不警告。这种 bug 只能靠盯类型发现。

6. 中控板焊完发现丢了 R2，算清楚它在电路里的作用并选了替代值。

---

## 二、知识点

### 1. ★★★ 传感器采集的固定套路：分压 → 反推阻值 → 查表

ADC 只能测电压，测不了电阻。所以所有电阻型传感器（光敏、土壤、热敏）都是先搭分压：

```
3V3 ── R(已知10k) ──┬── 传感器(未知R) ── GND
                    └── ADC 引脚
```

反推阻值的公式（分压比）：

```
R_传感器 = 10k × V / (3.3 − V)
```

几点必须记住：

- **光照越强 → 光敏阻值越小 → 分压点电压越低**（方向别记反）
- 这公式在 `V → 3.3` 时会**除零**，所以代码里要判一下 `3.3 - V` 是不是接近 0
- `V` 越接近 3.3，反推出的阻值误差被放大得越厉害

### 2. ★★ 为什么用查表不用公式

光敏电阻的阻值-照度是幂函数 `R = R10 × (E/10)^(−γ)`，看着能算，但：

- **STM32F103 没有硬件浮点单元（FPU）**，算一次幂函数要几千个周期
- 土壤探头的阻值-湿度和含水量更是没有解析式，厂家自己都只给曲线

所以标准做法是提前在电脑上算好一张表，运行时**线性查表**：数组从大到小排，找到第一个"阻值 ≥ 表项"就取对应的值。

```c
for (i = 0; i < sizeof(GL5528)/sizeof(GL5528[0]); i++) {
    lux = GL5528[i].lux;
    if (resistance >= GL5528[i].ohm) break;   // 数组必须降序
}
```

**用精度换速度**，这是嵌入式最常见的取舍。

### 3. ★★★ DMA 就是"不用 CPU 帮忙的搬运工"

- 没 DMA：老板（CPU）每收一个快递，自己跑一趟仓库
- 有 DMA：老板喊一声"帮我搬"，继续开会，搬运工自己干完

它解决的是"ADC 只有一个 DR、每转完必须马上读走"这个死结。有 DMA 之后，ADC 转完直接发请求，DMA 硬件把 DR 抄进数组，**一次中断都不用进**。

一句话分工：**ADC 负责量，DMA 负责搬，CPU 负责算。**

### 4. ★★ 五个必须理解的配置项

| 配置项 | 说明 | ADC 采集时 |
|---|---|---|
| 传输方向 | 外设→内存 / 内存→外设 / 内存→内存 | **外设→内存** |
| 数据宽度 | 8 / 16 / 32 位 | **Half Word（16 位）**，因为 DR 是 16 位 |
| 外设地址增量 | 搬完源地址要不要 +1 | **不增**（永远是 ADC_DR） |
| 内存地址增量 | 搬完目标地址要不要 +1 | **递增**（buf[0]→buf[1]） |
| 传输模式 | Normal / Circular | **Circular**，否则只搬一轮 |

### 5. ★★ 通道是硬连线，不能自己选

STM32F103 的 DMA1 有 7 个通道，每个通道绑死几个外设：

| 通道 | 常用外设 |
|---|---|
| **DMA1_Ch1** | **ADC1**、TIM2_CH3、TIM4_CH1 |
| DMA1_Ch4 | **USART1_TX**、SPI2_RX、I2C2_TX |
| DMA1_Ch5 | **USART1_RX**、SPI2_TX、I2C2_RX |

**用 ADC1 就只能占 DMA1 通道 1。** CubeMX 会自动选，但原理要懂。

### 6. ★★★ DMA 缓冲区绝对不能是局部变量

```c
void foo(void)
{
    uint16_t buf[2];                        // 错！函数一返回栈就没了
    HAL_ADC_Start_DMA(&hadc1, (uint32_t*)buf, 2);
}
```

DMA 是**独立于 CPU 运行**的，函数返回后它还在往那块内存写。必须用 `static uint16_t buf[2];` 或全局变量，否则轻则数据错乱，重则 HardFault。

### 7. ★★ 开了 DMA 就别再调 `HAL_ADC_GetValue()`

值已经被 DMA 搬走了，你再读 DR 读到的是下一次转换的半成品或旧值。**DMA 模式就只读数组。**

### 8. ★ 中控板的电源树

| 节点 | 挂什么 | 说明 |
|---|---|---|
| **VIN_5V** | CH340K、R2→LED3、C3/C4/C6 | **常电**，USB 一插就有 |
| **VCC5V** | AMS1117 输入、核心板 5V | 由 SW1 拨动开关从 VIN_5V 切过来 |
| **3V3** | AMS1117 输出、核心板、LED4、各模块 | 线性稳压，输入输出压差 1.7V |

**推理价值**：SW1 关着的时候 LED3 就该亮（VIN_5V 常电），LED4 不亮。这个现象一次能验四处焊接：USB 座、保险丝 F1、R2、LED3 极性。

## 三、踩的坑

1. **DMA 缓冲区写成局部数组**。编译、链接全过，运行起来数据乱跳，最难查的一类 bug。
2. **DMA 模式设成 Normal**，只搬一轮就停，数组里的值永远不变，还以为是 ADC 坏了。
3. **数据宽度选 Byte**，只搬低 8 位，数值全错。
4. **忘开扫描模式**，Number Of Conversion 写着 2，但第二个数组元素永远是 0。
5. **采样时间太短**，光敏内阻几十 kΩ，读出来偏小而且不稳。
6. **反推阻值时没防除零**，`V` 一旦接近 3.3V 程序就跑飞。

---

## 四、遗留

1. 多路 ADC + DMA 的代码只在 PC 上推演过，没上板实测数据。
2. 查表用的 GL5528 数据是网上抄的，没有实测校准。
3. 土壤湿度的分级阈值（1~4 档）很粗，实际用起来可能需要按自己土壤重新标定。
4. 中控板用 2k 替了 1k 的 R2，LED3 会偏暗（电流从 2.9mA 降到 1.45mA），等有 1k 再换回。

6. 学规则通道的转换顺序怎么排（SQR3/SQR2/SQR1 三个寄存器）。

---

## 二、知识点

### 1. ★★★ ADC 就是一把只有 4096 格的尺子

不管名字多唬人，它只做一件事：**给我一个 0~3.3V 的电压，还你一个 0~4095 的整数**。

```
输入 1.65V（正好一半）→ 2048
输入 0V              → 0
输入 3.3V            → 4095
```

格子数来自位数，`2^12 = 4096`：

| 位数 | 格子数 | 3.3V 下每格 |
|---|---|---|
| 8 位 | 256 | 12.9 mV |
| **12 位（F103）** | **4096** | **0.806 mV** |
| 16 位 | 65536 | 50 µV |

0.806mV 就是这颗芯片的极限：**电压变化小于它，数字不会变**。

两个方向的换算，代码里只用得着第二个：

```
电压 = 数字 × 3.3 / 4096      ← 天天用
数字 = 电压 / 3.3 × 4096      ← 理解用
```

### 2. ★★★ 采样 → 保持 → 量化 → 编码，就是给流水拍照

| 步骤 | 人话 | 硬件在干什么 |
|---|---|---|
| 采样 | 隔一会儿拍一张 | 把引脚电压接到内部小电容上 |
| 保持 | 把照片定格 | 断开输入，让电容电压冻住 |
| 量化 | 拿 4096 格的尺子量 | 逐次逼近（二分搜索）出最接近的整数格 |
| 编码 | 把"第几格"写成二进制 | 存进数据寄存器 |

**"保持"为什么必需**：量化要花几十个时钟周期，这期间输入要是还在变，量出来的结果对不上任何真实值。电容把电压冻住，量化才有稳定目标。

**逐次逼近怎么逼近**：就是猜数字。先猜量程一半 1.65V，比目标小就把最高位设 1，再猜 2.475V……比 12 次，正好出 12 位。

### 3. ★★ 分辨率 ≠ 精度

```
分辨率 = 尺子上有多少格   → 12 位 = 0.806mV 一格（硬件定死，改不了）
精度   = 尺子本身准不准   → 实际可能有 ±5mV 甚至更多（看设计）
```

VREF+ 接的 3.3V 实际可能是 3.28V，参考电压飘 20mV，所有读数整体偏移，精度就只剩 20mV 级别。**所以高精度场合要给 VREF 加滤波，模拟地和数字地分开走。**

### 4. ★★ 排转换顺序：写的是"数量 − 1"

一个 ADC 有 16 个外部通道，但**只有一个数据寄存器**。开了扫描模式后它必须知道先量谁，这个顺序存在三个寄存器里：

```
SQR3 → 第 1~6 个转换（每个通道占 5 bit）
SQR2 → 第 7~12 个
SQR1 → 第 13~16 个 + 序列长度 L[3:0]
```

依次量通道 0、2、5：

| 写哪 | 值 |
|---|---|
| `SQR3[4:0]`（SQ1） | 0 |
| `SQR3[9:5]`（SQ2） | 2 |
| `SQR3[14:10]`（SQ3） | 5 |
| `SQR1[3:0]`（L） | **2** ← 3 路写 2 |

两个必踩的坑：
1. **L 位写"通道数 − 1"**，写 3 会多转一个不存在的通道，读到垃圾。
2. **SQ1 在最右边（最低 5 位）**，不是序号越大越先转。

> CubeMX 里直接拖 Rank 顺序就行，寄存器它帮你算。但面试问原理，得知道。

### 5. ★ 采样时间不能设太短，跟信号源内阻有关

内部采样电容要充电到输入电压。源内阻越大充得越慢：

| 输入源内阻 | 建议采样周期 |
|---|---|
| < 10kΩ | 7.5 ~ 28.5 cycles |
| 10k ~ 50kΩ | 41.5 ~ 71.5 cycles |
| > 50kΩ | 239.5 cycles |

总转换时间 = `(采样周期 + 12.5) / ADC_CLK`。ADC_CLK 由 PCLK2 分频，**最大 14MHz**，72MHz 主频下只能选 6 分频（12MHz）或 8 分频。

### 6. ★ 三种模式，别搞混

| 模式 | 一句话 | 用在哪 |
|---|---|---|
| 单次 | 转一次就停 | 偶尔量一下 |
| 连续 | 转完立刻接着转 | 持续监控 |
| 扫描 | 一组多个通道按顺序转一遍 | 多路采集 |

**扫描模式不开，Number Of Conversion 设成 2 也没用**，只会转第一个。

### 7. ★★ 只有一个数据寄存器 → 这就是要学 DMA 的原因

16 个通道共用一个 DR：

```
通道 0 转完 → 写进 DR
通道 1 转完 → 覆盖 DR，通道 0 的值没了
通道 2 转完 → 又覆盖
```

多通道采集必须"每次转换完立刻把 DR 读走"。靠中断读，100kSPS 就是每秒 10 万次中断，CPU 全耗在进中断上。

---

## 三、踩的坑

1. **以为 12 位分辨率就是 12 位精度**。分辨率是格子数，精度看 VREF 稳不稳、噪声大不大，两回事。
2. **SQR 的 L 位填了通道数**（3），实际要填 2。结果多转一个空通道，数据错位。
3. **以为 SQ 序号越大越先转换**。SQ1 在最低位，是第一个转的。
4. **采样时间随手设 1.5 cycles**，光敏那种几十 kΩ 的源根本充不满电容，读数偏小而且乱跳。

---

## 四、遗留

1. 多通道采集会互相覆盖这件事，还没解决（要靠 DMA）。
2. 光敏、土壤的实际分压电路没搭起来，只会算不会用。
3. 内部温度传感器和 VREFINT 两个内部通道没试过。

## 二、知识点

### 1. ★★★ 单击 / 双击 / 长按的本质是"时间判定"，不是"中断"

三个状态就够：

| 状态 | 含义 | 出路 |
|---|---|---|
| `IDLE` | 松着，等按下 | 读到低电平 → `DOWN` |
| `DOWN` | 按着 | 满 800ms → 报长按；松手 → `WAIT_2ND` |
| `WAIT_2ND` | 松开了，等第二击 | 300ms 内又按下 → 报双击；超时 → 报单击 |

三条必须记住的结论：

- **单击一定要拖 300ms 才敢报**。按下那一刻没法区分"单击"和"双击的第一击"，只能先松开、再等一个窗口没有第二击，才确认是单击。代价是 0.3 秒延迟，人感觉不出来。
- **双击在第二次按下的瞬间就报**，不用等它松开。早报 100ms，手感差别很大。
- **必须有一个 `fired` 标志**，表示"这次按下已经消费过事件了"。否则长按松手会再补一个单击、双击松手也会再补一个单击，一次动作报两次。

> 用外部中断做不出这套东西 —— 中断只告诉你"电平变了一下"，不告诉你过了多久、第几次按。所以按键扫描放主循环，5ms 一次轮询，20ms 消抖（电平稳定 20ms 才采信）。

### 2. ★★★ 主循环里不许有 `HAL_Delay`，等待一律改成"查 tick"

蜂鸣器要"响 80ms、停 120ms"循环，最直观的写法是：

```c
BEEP_On();  HAL_Delay(80);
BEEP_Off(); HAL_Delay(120);
```

这一圈就把主循环锁死 200ms，按键丢了、串口不处理了。

正确做法是做一个"相位 + 剩余次数"的节拍器：

```c
typedef struct {
    uint16_t on_ms, off_ms;
    uint8_t  left;      /* 只剩几次；0xFF=无限 */
    uint8_t  phase;     /* 0=响 1=停 */
    uint32_t tick;      /* 进入当前相位的时刻 */
} beep_obj_t;
```

`BEEP_Tick()` 每圈只做一件事：看当前相位待够了没有，够了就翻转。
**"等待"这个东西一旦拆成"每隔一段时间检查一次"，主循环就再也不会被堵住。**

### 3. ★★★ 迟滞（回差）的解除门槛必须落在正常工作区里

迟滞本身是为了防抖动：超了才报、降下来才解除，中间留一段死区。

但今天连踩两次同一个坑：

| 场景 | 下限 | 室内实际值 | 解除门槛（下限+50） | 结果 |
|---|---|---|---|---|
| 第一次 | 400 | 417 | 450 | 417 够不到 → 永久卡 LOW |
| 第二次 | 300 | 350 | 350 | `350 > 350` 不成立 → 还是卡死 |

结论：**回差不是抄一个数就完事，它的解除门槛必须落在正常工作区里**。
高报用 50 没问题（1000 → 950 解除），低报只能给 10（300 → 310 解除，350 轻松越过）。

### 4. ★★ 帧头同步：错位要能自己爬回来

两种写法的差别：

| 写法 | 做法 | 一次丢字节后 |
|---|---|---|
| 收满再查 | 攒够 6 字节，看 `buf[0]` 是不是 `0x2C` | 永远从错的位置切 6 字节，回不来 |
| **逐字节找帧头** | 只在"还没开始拼帧"时认 `0x2C`，其他字节直接丢 | 下一个 `0x2C` 自动重新对齐 |

```c
if ((idx == 0) && (b != 0x2C)) continue;   /* 这就是全部秘密 */
```

配合双重校验更稳：校验和只能保证"6 个字节自洽"，错位帧偶尔也能撞对；再加一条"B4/B5 必须是固定的 `03 FF`"，相当于第二道身份验证。

### 5. ★★ 三层缓冲：谁写、谁读，必须分开

```
co2_rx_buf  ← HAL 直接写（中断上下文）
co2_frame   ← 拼帧工作区
co2_latest  ← 校验通过的快照，主循环只读这个
```

只留一份缓冲会读到"半新半旧"的 6 字节 —— 解析出来的浓度可能上万（把 `0x2C` 当成高位了）。
快照是 6 字节的连续拷贝，不会被自己打断；主循环读快照时，中断只会写工作区，天然不打架。

### 6. ★★ 上电的初始值不能直接拿去判断

`g_co2` 初值是 0，还没收到第一帧就去判"低于下限"，必然误报，还会被回差卡住。

```c
static uint8_t g_co2_valid = 0;   /* 收到第一帧才置 1 */
if (g_co2_valid == 0) return;      /* 数据无效，不判、不响 */
```

**"没有数据"和"数据是 0"是两件事**，代码里必须区分开。

### 7. ★★★ ARMCC 按 GBK 解析源文件，中文字符串会被拆坏

编译报错：

```
error: #53: expected a ":"
error: #8: missing closing quote
```

原因：源文件是 UTF-8，一个汉字占 3 字节；ARMCC 按系统本地编码 GBK 去读，2 字节算一个字，读到最后一个汉字时会多出半个字节，**这半个字节把字符串结尾的 `"` 吃掉了**。

| 中文在哪 | 会不会出事 |
|---|---|
| 注释里 | 不会，注释内容不参与语法 |
| 字符串字面量里 | **会，直接编译报错** |

三条出路：串口输出全用英文（最省事）／把文件转成 GBK（VS Code 打开乱码）／`\xNN` 转义（不可读）。

### 8. ★ 编译 ≠ 下载

`UV4.exe -b` 只生成 hex，不会烧进板子。
改完代码必须 F8（或 `UV4 -f`）重新下载，否则看到的现象还是旧逻辑 —— 今天为这个白等了一轮。

## 二、知识点

### 1. ★★★ 前后端框架：中断只搬数据，判断全归主循环

| | 后端（中断回调） | 前端（主循环） |
|---|---|---|
| 该干 | 拷数据、存长度、置标志、重开接收 | 判标志、比对、控外设、回显 |
| 不该干 | 发送、延时、字符串比对、长运算 | 无（想干多久干多久） |
| 原因 | 占用中断就丢数据、拖慢全局响应 | CPU 闲着也是闲着 |

- 标志位必须 `volatile`，否则编译器把它缓存进寄存器，主循环可能永远读到 0。
- 中断里 `HAL_UART_Transmit(..., HAL_MAX_DELAY)` 是双重错误：一是阻塞，二是 USART1 和 SysTick 同为抢占优先级 0，**tick 不涨，超时机制直接失效**。

### 2. ★★★ `ReceiveToIdle_IT` 的结束条件是"收满 Size **或** 总线空闲，先到先算"

- 第三个参数是**缓冲区容量上限**，不是"期望收到的长度"。
- IDLE（空闲）中断的物理含义：总线连续一个字节时间没有新数据。HAL 就认为一帧结束，回调里的 `Size` 是实际收到几个字节。
- 所以 3 字节的 `LED` 和 10 字节的 `LED_TOGGLE` 各算一帧，这就是"变长"。
- 老师给 10 字节缓冲，发 `LED_TOGGLE\r\n`（12 字节）必然被切成两帧 —— 这是隐藏的截断 bug。

### 3. ★★★ ORE 会让 HAL 自己把接收关掉，只能靠 `HAL_UART_ErrorCallback` 救

- 四种错误：PE（奇偶）、FE（帧）、NE（噪声）、ORE（溢出）。
- 前三种非阻塞，HAL 报一声继续收；**ORE 是阻塞错误**，`HAL_UART_IRQHandler()` 里会调 `UART_EndRxTransfer()`，关掉 RXNEIE/PEIE/EIE，`RxState` 归位，然后调 `HAL_UART_ErrorCallback()`。
- 回调是 `__weak` 空壳，不写就没人重开接收 → **静默死机：串口助手还在发，板子一个字不收，只能复位**。
- ORE 成因：`DR` 里上一个字节没读走，下一个又来了。现实触发源：Keil 打断点（CPU 停了硬件还在收）、波特率不匹配、线松动、把发送/延时塞进中断。

### 4. ★★★ 中断机制：向量表 + NVIC + 弱函数覆盖

| 概念 | 说明 |
|---|---|
| 向量表 | Flash 开头一张地址表，每个中断号一个入口，在 `startup_stm32f103xb.s` 里 |
| NVIC | Nested Vectored Interrupt Controller，嵌套向量中断控制器，管使能、优先级、嵌套 |
| ISR | 中断服务函数，就是普通 C 函数，不需要 8051 那种 `interrupt` 关键字 |

- 进中断时**硬件自动**压 8 个寄存器（R0-R3, R12, LR, PC, xPSR），返回时自动出栈，不用写汇编。
- `NVIC_PRIORITYGROUP_4` = 4 位全给抢占优先级，0~15，**数值越小越优先**。
- 本工程实际优先级：USART1 = 0（最高）、SysTick = 0、TIM3 = 1、EXTI15_10 = 3。
- HAL 的回调（`HAL_UARTEx_RxEventCallback` 等）在库里是 `__weak` 空实现，自己写同名函数就覆盖，**不用改 HAL 源码**。

### 5. ★★★ 中断里绝对不能 `HAL_Delay()`

- `HAL_Delay` 靠 SysTick 递增计时。若当前中断的抢占优先级 ≥ SysTick 的优先级，SysTick 进不来，`HAL_Delay` **永远出不来**。
- 本工程 USART1 = 0、SysTick = 0，同优先级不能互相抢占 → 中断里调 `HAL_Delay` 就是死等。

### 6. ★★ 数组名是地址常量，不能整体赋值

- `a = b;`（a、b 都是数组）在 C 里**非法**。数组名退化成 `&a[0]`，是常量，不能当左值。
- 拷贝内容只能 `memcpy(dst, src, n)` 或 for 循环。
- 连带规则：**`extern` 只是声明，不分配内存**。定义只能有一处（放 `.c`），头文件永远只放 `extern`。只声明不定义，编译期不报，**链接期报 `L6218E: Undefined symbol`**。

### 7. ★★ `strncmp` 和 `strcmp` 在串口场景里不是一回事

- 串口助手默认会补 `\r\n`，`strcmp("LED_ON", "LED_ON\r\n")` **永远不相等**。
- 用 `strncmp(buf, "LED_ON", 6)` 只比前 6 字节，把尾巴绕过去。
- 残留问题：缓冲区不清，先发长命令再发短命令会读上一次的残字，照样误匹配。解法是每次 `buf[len] = '\0'`（比整块 memset 更准）。

### 8. ★★ 单缓冲 + 标志位的三种竞态

| 竞态 | 怎么发生 | 后果 |
|---|---|---|
| 长度和数据不同步 | 主循环读 `g_rx_len` 时中断刚更新成新帧长度 | 拿新长度拷旧数据 |
| memcpy 撕裂 | 拷到一半，中断重开接收，硬件覆盖缓冲区 | 前半旧帧 + 后半新帧 |
| 标志被抹 | 拷完后、清标志前，中断置 1，主循环清 0 | **整帧静默丢失** |

- 唯一根治办法是**双缓冲轮换**或**环形队列（FIFO）**：中断只写 A，主循环只读 B，天然不打架。
- 但 115200 下一个字节 87µs、一帧 500µs+，主循环 memcpy 只要 1~2µs，撞上概率极低 → 教学作业不必上。
- 前提是**别去清中断的接收缓冲**，任何时刻清都可能把刚收到的字节抹成 0。

### 9. ★★ 工业串口和教学版差在哪

| 层面 | 教学版 | 工业版 |
|---|---|---|
| 物理层 | TTL 直连 | RS-485 差分（1200m）、隔离、TVS |
| 帧格式 | `"LED_ON\r\n"` | 帧头 + 长度 + 命令码 + 载荷 + CRC + 帧尾 |
| 切帧 | 字符串比对 | 状态机逐字节解析 |
| 校验 | 无 | CRC16（Modbus RTU 是事实标准） |
| 搬运 | 逐字节中断 | DMA + IDLE 中断，CPU 不参与 |
| 缓冲 | 单缓冲 + flag | 环形队列 |
| 可靠性 | 无 | ORE 计数恢复、丢帧、ACK/NAK 重发、超时进安全态、看门狗 |

## 一、干了什么

5. 踩完 CubeMX 的引脚复用冲突和 TIM1 部分重映射两个坑。

---

## 二、知识点

### 1. ★★★ 硬件 PWM 和软件 PWM 是两代东西

| | 软件 PWM（10.17 的 TIM3） | 硬件 PWM（今天的 TIM1） |
|---|---|---|
| 谁产生波形 | CPU 在中断里写 ODR | 定时器的 OC 比较器，纯硬件 |
| CPU 参与度 | 每半个周期进一次中断 | 只在改 CCR 那一瞬间动一下 |
| 1kHz 精度 | 受中断延迟影响，会抖 | 1µs，绝对稳 |
| 20kHz 可行性 | 72MHz 只剩 3600 个时钟，中断开销吃光 | 轻松 |

- 呼吸灯的 `while` 里只做两件事：改一个数、延时。**波不是它画的**。
- 常见误解：看到 `while` 里有延时，就说"这是轮询、应该挪到中断里翻电平"。这是把「谁产生波形」和「多久更新一次占空比」混成了一件事。前者已经由硬件接管，后者才轮得到软件优化。

### 2. ★★★ Pulse 就是 CCR 的初值

- `sConfigOC.Pulse = 300` 等价于 `TIM1->CCR1 = 300`，只在 `MX_TIM1_Init()` 时写一次。
- 占空比 = `CCR / (ARR+1)`。本例 ARR=999，所以 300 → 30%。
- 运行时想改，用 `__HAL_TIM_SetCompare()`，写的是同一个寄存器，**不用重新生成代码**。
- 边界：CCR=0 恒为无效电平，CCR > ARR 恒为有效电平（100%）。
- 规律：固定亮度改 Pulse，动态亮度用 `SetCompare`。呼吸灯里 Pulse 填什么都无所谓，1ms 后就被覆盖。

### 3. ★★★ 极性决定"有效电平"是高还是低

- `Polarity = High` → CNT < CCR 时输出**高**；`Low` → 输出**低**。
- 本板 LED 是 `3V3 → 330Ω → LED 阳极 → 引脚`，**低电平点亮**。
- 两条结论：
  - High 极性下，CCR 越大 → 高电平越长 → **灯越暗**（299 亮 70%，899 亮 10%）；
  - Low 极性下，CCR 才等于亮度百分比（CCR=899 亮 90%）。
- 记住链条：**CCR 管的是"有效电平"占比，亮度 = 有效电平占比 × 灯的极性**。中间隔着一层，不能直接等同。

### 4. ★★★ 一个定时器能同时驱动多路：共用时基，独立 CCR

- CH1 和 CH3 共享同一个 PSC/ARR → **频率必然相同**，没法各跑各的。
- CCR1、CCR3 是两个独立寄存器 → **占空比各设各的**。
- 这就是硬件 PWM 的性价比：配一次，几路波形并行走，CPU 零负担。

### 5. ★★ CH3N 是互补通道，启动函数带 Ex

| 通道 | 启动函数 |
|---|---|
| CH1 / CH3（主通道） | `HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_x)` |
| CH3N（互补通道） | `HAL_TIMEx_PWMN_Start(&htim1, TIM_CHANNEL_3)` |

- **只有高级定时器（TIM1 / TIM8）才有 N 通道**，TIM2/3/4 是通用定时器，下拉框里根本不会有 `PWM Generation CHxN`。
- 两个函数内部都会置 **MOE**（Main Output Enable，主输出总闸），不用自己手写。
- CH3N 的极性归 `OCNPolarity` 管，和 CH3 的 `OCPolarity` 是两个字段。

### 6. ★★ TIM1 部分重映射会连累无关引脚

- F103 的 TIM1 有三套映射，常用两套：

| 信号 | 默认映射 | 部分重映射 |
|---|---|---|
| CH1 | PA8 | PB13 |
| CH3 | PA10 | **PB15** |
| CH3N | **PB15** | **PB1** |
| BKIN | PA6 | **PB12** |

- 一旦 CH3N 落到 PB1，整颗 TIM1 就进入部分重映射：PB15 从 CH3N 变成 CH3，BKIN 从 PA6 变成 PB12，于是和 SW2 的 EXTI12 撞车，CubeMX 报红。
- 那个红色警告**不是 Break 功能要开**，是在说"这套重映射方案需要 PB12"。
- 破局：先清空所有触发重映射的引脚（Channel 改 Disable），回到默认映射，再重新选。默认映射下 CH3N 的唯一候选就是 PB15。

---

## 三、踩的坑

1. **改了界面不等于改了文件** —— 忘了点 GENERATE CODE，`.ioc` 和 `tim.c` 一个字没变，白配一轮。CubeMX 只有生成或 Ctrl+S 才写盘。
2. **引脚没释放就想选 PWM 通道** —— PA8 还是 `GPIO_Output`，Channel1 下拉里的 `PWM Generation CH1` 是灰的。一个引脚同一时刻只能有一种身份，必须先 Delete 掉旧身份。
3. **CubeMX 把 CH3N 自动分到 PB1** —— 因为 PB15 当时还被 `LED2_GPIO_Output` 占着，它退而求其次用了重映射引脚，顺带把 BKIN 拖到 PB12 上制造出一堆假冲突。无视警告、直接在 PB15 上强行指定 `TIM1_CH3N` 反而一次成功。
4. **以为 CCR 变大就该变亮** —— 忽略了"有效电平 = 高电平"和"灯是低电平点亮"这两层，方向正好反。
5. **重新生成把 CH1 的极性和 Pulse 重置了** —— CubeMX 只保护 `USER CODE` 区，外设参数全按 `.ioc` 重写。改完别的通道，回头要检查原通道的参数还在不在。
6. **把"中断里翻电平"当成优化** —— 那是退回软件 PWM，波形精度反而下降。真要腾 CPU，该动的是"多久改一次 CCR"，不是"谁产生波形"。

## 四、遗留

1. 硬件 PWM 只做到了"主循环里改 CCR"。**定时器更新中断里改 CCR**、**DMA 喂波形表**都还没试。
2. 呼吸灯是 0→1000 线性变化，人眼按平方律感知，看着"亮得快、暗得慢"。Gamma 校正（`ccr = i*i/1000`）没验证。
3. **串口 printf 重定向还没做**（10.13 就挂了账），后面调试只能靠肉眼。

5. 把 TIM3 的 1ms 中断改成软件 PWM，实现 20% / 50% / 80% 三档亮度循环。

## 二、知识点

### 1. ★★★ 推挽 vs 开漏

| 维度 | 推挽 Push-Pull | 开漏 Open-Drain |
|---|---|---|
| 内部结构 | 上管 + 下管 | 只有下管 |
| 输出高 | 主动拉 VDD，低阻 | 高阻，靠外部上拉拉高 |
| 输出低 | 主动拉 GND | 主动拉 GND（相同） |
| 外接上拉 | 不需要 | **必须**，否则测不到高电平 |
| 高电平值 | 只能是自己的 VDD | 上拉到几伏就是几伏 |
| 上升沿 | 快（主动驱动） | 慢（受 R×C 充电限制） |
| 能否线与 | 不能，对接会短路 | 能，多脚共享一根线 |
| 典型场景 | LED、蜂鸣器、片选 | I2C、SMBus、共享中断线、电平转换 |

- **推挽是"自己出力"，开漏是"只会往下拉，高的靠别人"**。
- 线与（wired-AND）：多个开漏脚共用一个上拉，**全高才高，任一拉低就低**——I2C 总线仲裁和时钟同步的物理基础，所以 **I2C 必须开漏**。
- 上拉电阻 4.7k~10k：太大上升沿被 RC 拖慢，太小输出低时静态电流白烧。STM32 内部上拉只有 30~50kΩ，很弱，正式总线必须外接。
- 开漏要输出 5V，引脚必须查手册标 **FT**（5V Tolerant，5V 容忍），非 FT 脚灌 5V 会烧。

### 2. ★★★ 中断回调里的变量必须是静态的

- `volatile uint32_t count = 0;` 写在函数**内部** → 每次进中断都重新初始化 → count 永远等于 1 → `count % 5 == 0` 永不成立 → 一次都不翻转。
- 局部变量有**自动存储期**，函数每次进入都是全新的一份。要在多次中断之间累计状态，必须让它活到函数外面：

```c
static volatile uint32_t count = 0;   // 放在函数外
```

- `volatile` 管的是"编译器不许把这个变量缓存进寄存器"，**不管生命周期**。两个问题互相独立，别混。

### 3. ★★★ `HAL_GPIO_TogglePin` 只能做 50% 占空比

- `TogglePin` 就是 `ODR ^= pin`，它只能决定"什么时候换状态"，**换完之后要等多久才换回来，被同一个间隔绑死了**。
- 所以翻转间隔不管取 1ms、5ms 还是 500ms，高电平时间和低电平时间永远相等 → 占空比恒为 50%。
- 要做非 50%，必须**在两个不同时刻下两个不同的命令**：

```c
if (t < low_ms)  WritePin(..., GPIO_PIN_RESET);   // 前 low_ms 亮
else             WritePin(..., GPIO_PIN_SET);     // 其余时间灭
```

- ★ toggle 有个好处：`%` 天然循环，**不用手动归零**，不会冻结。用它做 50% 方波是最省事的写法。

### 4. ★★★ 软件 PWM 的三要素

| 要素 | 作用 | 本例取值 |
|---|---|---|
| 时基 | 最小时间刻度，必须是周期中断 | TIM3 每 1ms |
| PWM 周期 | 决定闪烁频率，要高于人眼融合频率（约 60~90Hz） | 20ms → 50Hz |
| 占空比阈值 | 一个周期内保持有效电平的时长 | 4 / 10 / 16 ms |

```c
t = count % 20;                 // 周期内位置
low_ms = (phase == 0) ? 4 : (phase == 1) ? 10 : 16;
if (t < low_ms) 低电平; else 高电平;
```

- **亮度只看占空比，频率只决定闪不闪**。50% 波形在 1Hz 下是"闪"，在 100Hz 下就是"稳定半亮"。

### 5. ★★ 递减计数模式下 PWM 模式 1 的波形

| CNT 方向 | 通道为有效电平的条件 | 波形（有效=高） |
|---|---|---|
| 递增 Up | `CNT < CCR1` | 先高后低 |
| 递减 Down | `CNT ≤ CCR1` | **先低后高** |
| 中心对齐 | 上下交替 | 高电平居中，两侧对称 |

- 递减时 CNT 从 ARR 一上来就 `> CCR1`，所以**开头是无效电平**，减到 CCR1 之下才翻成有效。等于把递增模式的波形**水平镜像**，占空比数值基本不变，只是高电平从周期前段挪到后段。
- 边界差 1 个计数：递增是 `CCR1/(ARR+1)`，递减是 `(CCR1+1)/(ARR+1)`，因为包含 `CNT == CCR1` 那个点。
- 实际选型：**LED/蜂鸣器一律 Up**（相位对视觉零影响，公式最干净）；**无刷电机/逆变用中心对齐**（边沿对称，谐波小）；Down 基本不用。

## 三、踩的坑

1. **`HAL_TIM_Base_Start_IT` 漏写一个，编译照样 0 error** —— 启动的是 TIM1、TIM2，点灯代码却全在 `htim->Instance == TIM3` 分支里，于是中断永不进、回调永不执行。编译器不会提醒"你启动的定时器和用到的不是同一个"。
2. **把 `count` 写在回调函数里面，还加了 `volatile` 以为就万事大吉** —— `volatile` 只防止被优化掉，救不了作用域。每次进中断都从 0 开始，条件永远不成立。
3. **注释写"20% 占空比"，代码实际是 50%** —— 三个分支拆开算：`%5==0` 翻一次周期 10ms、`%5!=0` 翻一次周期 2ms，**占空比全是 50%**，三档亮度完全一样，所以就算灯亮了也看不出阶梯变化。
4. **手画 PWM 输出波形画出了三个电平** —— 推挽输出只有高、低两态，没有"半高"那个档。递减模式正确画法是每周期**先低后高**的方波。
5. **`count` 累加到 3000 之后没有归零** —— 三个 if 分支全都不成立，灯冻结在最后一帧，看上去像"程序卡死"。

## 四、遗留

1. 软件 PWM 三档亮度（20% / 50% / 80%）还没烧录验证。

4. 备考软考中级。

5. 把定时器中断和主循环里 `HAL_Delay` 两种点灯方式做了对比。

---

## 二、知识点

### 1. ★★★ 周期的两个旋钮：PSC 和 ARR

```
T = (PSC + 1) × (ARR + 1) / TIMxCLK
```

- TIM2/3/4 挂在 APB1，但 APB1 = 36MHz 且预分频 ≠ 1 → **定时器时钟实际是 72MHz**。
- **PSC 决定"一格多长"，ARR 决定"数多少格"**，两者相乘才是一个周期。
- 两种好用的配方：

| PSC | 1 格 | ARR 公式 | 例子 |
|---|---|---|---|
| 71 | 1µs | ARR = 周期(µs) − 1 | 1ms → 999 |
| 7199 | 0.1ms | ARR = 周期(ms) × 10 − 1 | 500ms → 4999、1s → 9999 |

- ★ 那个 `− 1` 别丢：计数器是 **0 → ARR**，共 ARR+1 格。

### 2. ★★★ ARR 是 16 位 → 一个 PSC 通吃不了所有周期

- PSC / ARR 最大都是 65535。PSC=71 时，理论最长只有 **65.5ms**，做不了 500ms。
- 反过来 PSC 取 7199 时，1ms 只剩下 ARR=9（太糙，步进 0.1ms 没法微调）。
- 所以 **1ms 和 500ms 必须用两个不同的 PSC**，这不是设计错误。
- 原则：**同周期下尽量让 ARR 取大一点**，留调节余地。

### 3. ★★★ 中断是怎么把 LED 翻起来的

- 没有"循环调用"，也没有"定时器接管某个函数"。真实链条：

```
TIM 数满 → 发中断请求 → CPU 跳进 TIMx_IRQHandler()
        → HAL_TIM_IRQHandler(&htimx) → HAL_TIM_PeriodElapsedCallback()  ← 自己写的
```

- `HAL_TIM_PeriodElapsedCallback` 是 HAL 预留的空壳，**里面写什么，中断就干什么**（翻转引脚、计数、打印都行）。
- 执行次数 = 中断次数，不是函数自己在循环。
- `HAL_TIM_Base_Start_IT()` 里的 `_IT` = Interrupt，这行不写就永远不进中断（CubeMX 不会替你加）。

### 4. ★★★ 定时器中断 vs 主循环 `HAL_Delay`

| | while + `HAL_Delay(1000)` | 定时器中断 |
|---|---|---|
| 本质 | 阻塞，CPU 干等 | 非阻塞，到点被打断 |
| 能同时干别的 | 不能，按键要等它转回来 | 能 |
| 精度 | 差（周期 = 延时 + 其他代码耗时） | 准（纯硬件计数） |
| 加第二个周期 | 麻烦 | 再加个定时器就行 |

- 一句话：`HAL_Delay` 是「用中断做延时，**让人在那等**」；定时器是「**用中断做事，不等**」。

### 5. ★★★ TIM1 是高级定时器，比 TIM2/3/4 多两个坑

| 项目 | TIM2/3/4 | TIM1/TIM8 |
|---|---|---|
| Repetition Counter | **没有这个框** | 有，**必须填 0**，填 1 周期翻倍 |
| NVIC 中断向量 | 只有 1 个 | **4 个**（break / **update** / trigger&comm / capture） |

- 做周期中断**只勾 `TIM1 update interrupt`**，勾错（比如勾了 break）程序编得过但回调永不执行。
- 对应的中断服务函数是 `TIM1_UP_IRQHandler()`，不是 `TIM1_IRQHandler()`。

### 6. ★★ Clock Source 为什么有时是下拉、有时是复选框

- CubeMX 的规则：**可用时钟源候选 > 1 个 → 下拉框；只剩 Internal Clock 一个 → 复选框**。
- 根因是**封装引脚**，不是总线：
  - TIM2 的 ETR 脚 = PA0，LQFP48 上有 → 多一个外部时钟选项 → 下拉
  - TIM3_ETR = PD2、TIM4_ETR = PE0，**LQFP48 根本没这两根脚** → ETR 选项被删掉 → 只剩 Internal Clock
- TIM3/TIM4 不是功能被阉割，外部时钟模式改从 **Slave Mode → External Clock Mode 1 + Trigger Source** 进。

### 7. ★★ APB1 / APB2 与定时器时钟

- 归属是硬件定死的：**TIM1 → APB2**；**TIM2/3/4/5/6/7 → APB1**。
- 参考手册的倍频规则：**APB 预分频 = 1 → TIMxCLK = PCLKx；≠ 1 → TIMxCLK = PCLKx × 2**。
  - APB1 ÷2 → 36 × 2 = **72MHz**
  - APB2 ÷1 → 72 × 1 = **72MHz**
- 两条总线的定时器时钟此刻数值相同，所以 PSC/ARR 对 TIM1 和 TIM2/3/4 算法完全一样。
- ⚠️ 一旦改了 APB 预分频，这个 72 就变了，PSC/ARR 必须重算。

### 8. ★★ 多个定时器能共存，互不干扰

- 硬件上就是两个独立外设：独立寄存器、独立时钟使能位、独立中断向量。**同一条总线只共享"时钟来源"，不共享计数器。**
- ⚠️ **全工程只有一份 `HAL_TIM_PeriodElapsedCallback()`**，所有定时器都往它跑 → **必须用 `htim->Instance` 区分**，否则 TIM1 到点会去翻 LED2。
- 两个定时器同优先级（默认 0,0）时**不能互相抢占，只能排队**，反而最安全。
- TIM1 控 PA8（GPIOA）、TIM2 控 PB15（GPIOB）**跨端口**，连 GPIO 竞态都没有。

---

## 三、踩的坑

1. **改周期改错了地方，白忙一场** —— 在代码里改、或在 CubeMX 里改了值没保存/没点 GENERATE CODE，`tim.c` 里的 ARR 还是旧的，烧进去当然没变化。**改周期只认 `.ioc` → 保存 → 生成 → 编码转换 → Rebuild**，一步都不能少。
2. **任务书写错了**：提示"定时器3挂载到APB2总线"，但它自己配的总线互连图上，TIM3 明明在 APB1 那一列（和 USART2/3、SPI2/3、I2C1 一起）。硬件的总线归属改不了。
3. **PC13 不是普通 IO** —— 它属于备份域（VBAT 供电的 RTC 区域），F103 的 PC13/PC14/PC15 只能 2MHz、约 3mA，点 LED 会偏暗，限流电阻得加大。而且我们板子上 PC13 压根没接灯。
4. **两个定时器翻同一个灯会打架** —— 不同周期抢着翻同一根引脚，灯会闪得乱七八糟。

### 2. ★★★ 下载器的选择存在 `.uvoptx`，不在 `.uvprojx`

| 文件 | 管什么 |
|---|---|

### 3. ★★★ 按键有两种模型：事件型 vs 状态型

| | 事件型（按一下翻转 / 计数） | 状态型（按住亮、抬起灭） |
|---|---|---|
| 问的是 | "刚才发生了什么" | "现在是什么样" |

- 中断里**不能延时**：`HAL_Delay` 靠 SysTick 中断计数，在中断里等它等于自己卡死自己（EXTI 优先级还比 SysTick 高）。

- 抖动会让中断被多叫几次，但每次都重写 LED 的**绝对电平** → 最终状态一定正确。

### 6. ★★ 改 EXTI 触发方式只动两个地方，不用跑 CubeMX

- `.ioc` 里：`PBxx.GPIO_ModeDefaultEXTI`（`GPIO_MODE_IT_FALLING` / `GPIO_MODE_IT_RISING_FALLING` / `GPIO_MODE_IT_RISING`）；
- 生成物 `gpio.c` 里：`GPIO_InitStruct.Mode`。

# 10.14 笔记

## 一、干了什么

1. 沿着网络编程题库 Q11（长连接怎么保活）往下挖了三轮：**TCP 断链怎么检测 → 语音终端项目当年怎么做的 → 以后是不是都该上心跳**；顺带把语音终端的板子端（`board/main.c`、`net.c`）和服务端（`server/server.py`）翻了一遍。
2. 做了一轮网络编程八股自测：抽 8 题默答，得分 62%，暴露多路复用、TCP 可靠性、粘包、TIME_WAIT 四个薄弱点。

---

## 二、知识点

### 1. ★★★ TCP 断链只有三种情况能被应用感知

| 对端发生了什么 | 应用能感知吗 | 怎么感知 |
|---|---|---|
| 正常关闭，发 FIN | 能（免费） | `read` 返回 **0** |
| 进程崩溃/重启，发 RST | 能（免费） | `read`/`send` 返 -1，`errno = ECONNRESET` |
| **断电 / 拔网线 / NAT 表项老化** | **不能** | 没有任何包，`read` 永久阻塞（半开连接） |

- 第三种才是长连接真正的敌人，必须**主动探测**。
- 「连接」只是通信两端内核各存一份 TCB（传输控制块），网络上没有连接的实体。

### 2. ★★★ 多路复用是「单线程管多个 fd」，不是「多进程通信」

- 用 `select` / `poll` / `epoll` 同时监视多个文件描述符，**谁就绪就处理谁**（事件驱动 IO）。
- 价值：一个线程管上万条连接，省掉每连接开一线程的开销（解决 C10K）。

### 3. ★★★ TCP 可靠性靠四大机制（缺一不可）

1. 序号 + 确认应答（ACK）—— 保证不丢、不乱序；
2. 超时重传（靠 RTO，重传超时）—— 没收到 ACK 就重发；
3. 滑动窗口 —— 流量控制，别把接收方撑爆；
4. 拥塞控制（慢启动 / 拥塞避免 / 快重传 / 快恢复）—— 别把网络撑爆。

另加校验和（数据完整性）+ 连接管理（三次握手四次挥手）。
★ 术语别错：是**重传**（TCP 层动作），不是重连（应用层重新建连接）。

### 4. ★★ 心跳 vs Keepalive：判据只看一条

- **判据：这条连接会不会长时间没有业务数据？会 → 上应用层心跳；不会 → 业务包本身就是心跳。**（心跳不是长连接的标配，是**空闲**长连接的标配）
- 应用层心跳探的是「**对方进程**还活着吗」，能发现应用假死；Keepalive 只能探到对端主机/内核没了。
- Keepalive 默认空闲 **2 小时**才开始探测、每 75s 一次、连 9 次才判死，且**穿不过 NAT** → 只能当兜底。
- 落地必须配套三件事：**超时判活（连续 N 次才算死）+ 退避重连 + 状态恢复（重登录/重订阅）**；服务端也要能清僵尸连接。
- 间隔取 **30~60s**，硬约束是**小于链路上 NAT/防火墙的最短老化时间**。

### 5. ★★ 粘包的根因是「TCP 是字节流，不保留消息边界」

- 三种解法：① 定长发送；② 尾部标记序列（包尾加特殊序列）；③ **头部定长包 + 长度字段**（语音终端用的这种）。
- 说法要严谨：TCP 里没有「包」只有字节流，「粘包」本质是**读取边界不清**。

### 6. ★★ TIME_WAIT 的两个作用（时长 2MSL）

1. **确保最后一个 ACK 能到达服务端**：这个 ACK 丢了服务端会重传 FIN，客户端还在才能补发；
2. **让本次连接的旧报文在网络中消亡**，避免串进复用相同四元组的新连接。
- 2MSL = 两个报文最大生存时间，传统实现 MSL 取 30s → TIME_WAIT 维持 1~4 分钟。

### 7. ★★ 语音终端项目的保活方案（实况）与两个隐患

- 方案：**没有心跳、也没开 SO_KEEPALIVE**，靠 `SO_RCVTIMEO / SO_SNDTIMEO = 5 秒` + 双层循环（外层重连 / 内层对话）判链；服务端靠 `recv` 返空收尾。
- 之所以够用：每轮都有 96KB 上行 + 命令下行，**连接从不空闲**，业务包自带探活。
- 隐患 1：服务端 `recv` 没超时 + 单线程 `accept` → 对端断电/被 kill（不发 FIN）时会永久卡在旧连接上，新连接没人接；
- 隐患 2：5 秒超时硬编码，ASR 慢时会误判断链（能自愈，但白扔一轮）。

## 二、知识点

### 1. ★★★ 时钟树是「约束推导」出来的，不是背下来的

- 硬上限（数据手册）：SYSCLK / HCLK ≤ **72MHz**、APB1 ≤ **36MHz**、APB2 ≤ **72MHz**、ADC ≤ **14MHz**、USB 必须精确 **48MHz**。
- 所以 8MHz 晶振 ×9 = 72MHz 之后，APB1 **必须** /2（因为 72 > 36）。
- 分频系数不是约定值，是「为了不超上限」算出来的；超限时 CubeMX 会直接标红。
- 默认复位态是 HSI 8MHz 全 /1 —— 能用，但慢 9 倍，且内部 RC 精度只有 ±1% 左右。

### 2. ★★★ CubeMX 只生成初始化骨架，不生成业务逻辑

- 它生成的是：时钟树、GPIO 模式、外设寄存器配置、中断向量 —— 把硬件摆成「可用状态」。
- 它**不知道**你的灯要怎么闪、按键按下要干什么。功能永远得自己写。
- `/* USER CODE BEGIN x */ ... /* USER CODE END x */` 之间才是自己的地盘；**写在保护区外的代码，下次点 Generate Code 会被模板覆盖**。

### 3. ★★★ 裸机 vs 嵌入式 Linux 是两条平行路线

| | 裸机单片机（STM32） | 嵌入式 Linux（GEC6818） |
|---|---|---|
| 板上有 OS 吗 | 没有，上电直接跑 `main()` | 有，跑着 Linux 内核 |
| 程序形态 | 烧进 Flash 的固件 | 文件系统里的一个进程 |
| 编译器 | armcc / arm-none-eabi-gcc | arm-linux-gcc（交叉编译） |
| C 库 | 无（或精简 newlib） | 完整 glibc |
| 典型调试 | J-Link + SWD 硬件调试 | printf / gdb 远程调试 |

- 「工具链仅支持 Windows」约束的是**宿主机**（你的电脑），跟目标板上跑什么毫无关系。

### 4. ★★★ 继电器驱动电路

```
GPIO ──> 限流电阻(1kΩ) ──> NPN 三极管基极
                              ↓ 导通
                        线圈得电（VCC → 线圈 → C → E → GND）──> 吸合「咔哒」
```

- **为什么必须用三极管**：GPIO 只能给几 mA，继电器线圈要 70mA 左右，**直接驱动必烧**。
- **续流二极管**（反并联在线圈两端）：线圈是电感，断电瞬间会感应出几百伏的反向尖峰，二极管给它一条泄放回路保护三极管。**绝对不能拆。**
- 触点引出三个端子：**COM**（公共端）、**NO**（常开端，吸合时与 COM 通）、**NC**（常闭端，不动作时与 COM 通）。
- **验证方法**：听「咔哒」声就够；或万用表通断档测 COM-NO / NC 的通断变化 —— 两种都**不需要外接任何负载**。

### 5. ★★★ PC13 / PC14 / PC15 是特殊脚

- **PC14 / PC15 兼作 LSE 晶振脚**（OSC32_IN / OSC32_OUT）：板上若焊了 32.768kHz 晶振（供 RTC 走时），这两个脚就不能再当普通 IO 用。
- 这三个脚的**最大输出电流只有 3mA**（普通 IO 是 20mA），所以只能配 `GPIO_SPEED_FREQ_LOW`。
- 本例：PC14 经 1kΩ 驱动 S8050 基极，Ib ≈ (3.3 − 0.7) / 1k = **2.6mA**，而三极管只需要约 0.84mA —— 有 3 倍余量，够用。

### 6. ★★ `WritePin` 与 `TogglePin` 的区别

| 函数 | 语义 | 结果 |
|---|---|---|
| `HAL_GPIO_WritePin(pin, GPIO_PIN_SET / RESET)` | **绝对**：设成明确电平 | 高 / 低 |
| `HAL_GPIO_TogglePin(pin)` | **相对**：翻转（内部就是 `ODR ^= pin`） | 取决于当前值 |

- 用 `TogglePin` 等于把「当前状态」这个信息**存在自己脑子里**，一旦别处也动过这个脚，你以为的状态和实际就对不上。
- **它最合适的场景**：周期翻转（LED 闪烁、蜂鸣器鸣叫）—— 本来就无所谓当前是高是低。
- **凡是要「变成确定状态」的场合**（开关型外设），一律用 `WritePin` + 自己的状态变量。

### 7. ★★ 蜂鸣器有源 / 无源

| | 有源 | 无源 |
|---|---|---|
| 内部 | 自带振荡电路 | 只有发声片 |
| 驱动 | 给高低电平就响 | 必须给方波，频率决定音调 |
| 调音量 | 软件改不了 | PWM 占空比可调 |

- 有源蜂鸣器**没有「半响」这回事**：GPIO 输出的是数字量。想安静只能**缩短响的时间**（占空比）或物理隔音。
- 判断方法：用 1Hz 方波驱动还能持续响 → 有源（无源只会「咔哒」）。

## 三、踩的坑

1. **`while(1)` 里的代码全被自己注释掉了** —— 程序在空转，灯当然不亮；**能编译通过 ≠ 在干活**。
2. **以为 CubeMX 会一键生成全部功能代码** —— 于是把自己写的逻辑注释掉「等它生成」。它只管配硬件，功能得自己写。
3. **端口和编号搞混** —— 想点 PB15 写成 `GPIOA, GPIO_PIN_15`（那是 PA15）；而 PA15 还是 JTAG 的 JTDI 脚，复位后归调试口，本来就不该走这条路。引脚名要拆成两半读：**P + 端口字母 + 编号**，端口和编号是两个独立维度。
4. **引脚没在 CubeMX 里配置就写操作代码** —— 编译照样过，运行时毫无反应（该脚仍是默认浮空输入）。
5. **调用不存在的函数** —— C 在编译期只给个 `declared implicitly` 警告，**到链接期才报 `L6218E: Undefined symbol`**，报错位置和真实原因隔了一层。
6. **蜂鸣器的 `TogglePin` 写在按键 `if` 分支里** —— 不按键就永远走不到那行，所以「怎么都不响」。**想让某件事无条件发生，就不能把它放在任何 `if` 里面。**

## 二、知识点

### 1. ★★★ 结构体内存大小 = 内存对齐的结果，不是成员大小之和

1. 第一个成员在偏移 0；
2. 后续成员对齐到「自身大小」与「编译器默认对齐数」取**较小值**的整数倍（VS 默认 8，32 位 GCC 常为 4）；
3. 结构体总大小补到「最宽成员对齐数」的整数倍。

```c
struct S { char a; int b; char c; };   /* 1 + 3(补) + 4 + 1 + 3(补) = 12 字节，不是 6 */
```

- `#pragma pack(n)` 可改对齐数，通信协议 / 寄存器映射的结构体常用。

### 2. ★★ sizeof 算的是「占多少字节」，不是字符串长度

| | sizeof | strlen |
|---|---|---|
| 本质 | 运算符，编译期确定 | 库函数，运行期逐个字符数 |
| 终止 | 不是靠 `'\0'`，算的是对象字节数 | 遇 `'\0'` 停 |
| 参数 | 类型 / 变量 / 数组 | 必须是 `char *` |

- `char s[] = "abc"` → sizeof = **4**（3 字符 + `'\0'`）；
- `char *p = "abc"` → sizeof(p) = **8**（64 位指针大小），**不是 4**。
- 所以「sizeof 会把 `'\0'` 算上」只对**数组**成立，对指针完全错。

### 3. ★★ memcpy 的关键在第三个参数（字节数）

- `strcpy`：只能拷字符串、遇 `'\0'` 停、**不指定长度** → 目标缓冲区不够就溢出。
- `memcpy`：由第三个参数指定拷贝**字节数**，能拷二进制 / 结构体；但要求源和目标**不重叠**，重叠必须用 `memmove`。

### 4. ★★ 两条容易说错的措辞

| 问题 | 容易说错 | 正确说法 |
|---|---|---|
| static 修饰局部变量 | 「生命周期变成全局」 | 生命周期变**全程**（挪到静态存储区，只初始化一次、默认清零）；**作用域不变**，仍只在函数内可见 |
| C 语言内存分布 | 只答「栈/堆/全局/常量/代码」五个名词 | 按**五块**答 + 说职责：栈（局部变量、函数参数）、堆（malloc 申请）、全局静态区（.data / .bss）、常量区（只读字面量）、代码区（.text） |

---

## 三、踩的坑

2. **把 sizeof 当成「求字符串长度」的工具** —— 在指针上直接崩（`char *p` 得 8，不是字符数）。
3. **memcpy 只答「能拷二进制」** —— 漏掉第三个参数（字节数）和「源目标不可重叠」这两个真正的差异点。

## 二、知识点

### 1. ★★★ 开关电源的整流二极管必须用肖特基，不能用 1N4007

**判断依据是"反向恢复时间 trr" 与"开关周期"的比值。**

MT3608 开关频率 **1.2MHz** → 周期 `1/1.2MHz = 833ns`。
而 1N4007 是**工频整流管**，trr ≈ **2µs（2000ns）**，是开关周期的 **2.4 倍**。

| 后果 | 说明 |
|---|---|
| 升不上去 | 管子还没恢复，下个开关周期已开始，输出根本到不了 12V |
| 严重发热 | 恢复期间 SW 节点到输出几乎短路 |
| 效率暴跌 | 正向压降 1.1V（肖特基只要 0.3~0.5V） |

**判据**：**高频开关电路（>100kHz）一律用肖特基**，耐压只要 > 输出电压即可
（耐压越高 VF 越大、效率越低，**不是越大越好**）。
本设计 12V 输出 → 选 **SS24 / SS34**（40V/2A、40V/3A，SMA 封装）就够。

> 同类：1N4007 属于**低频**器件，凡是 1MHz 级别的电路都不要用。

### 2. ★★★ 网络名是一个"真实的电气名"，不是注释

- `Global Net Name` 里写什么，**网表里就是什么**。写 `+5V（外部提供）` 会让**整个网络名都变成这个中文串**。
- **命名规范**：只用 **ASCII + 下划线**，例如 `V5V0`、`V12V0`、`V5V0_EXT`。
  **不要用** `+`、`-`、`.`、空格、全角括号。
- 想在图面上做提示，用**独立的 TEXT 注释工具**，别塞进网络名。

**为什么较真**：导出网表、做 BOM、与其他工具对接时，中文全角符号容易出编码问题。

### 3. ★★★ 反馈分压决定输出电压：Vout = Vref × (1 + R1/R2)

MT3608 的基准电压 **Vref = 0.6V**。本设计 `R1 = 47.5kΩ`（VOUT→FB）、`R2 = 2.5kΩ`（FB→GND）：

```
Vout = 0.6 × (1 + 47.5/2.5) = 0.6 × (1 + 19) = 12.0V   ✓
```

**反馈电阻必须精密**（用 ±1%），因为分压比直接线性决定输出电压误差。

### 4. ★★ 升压电感纹波电流怎么算

```
占空比      D  = 1 − Vin/Vout = 1 − 5/12 = 0.583
纹波电流    ΔIL = Vin × D / (f × L) = 5 × 0.583 / (1.2MHz × 4.7µH) ≈ 0.52A
```

- **感值越大，纹波越小**：换成 10µH → 0.24A；22µH → 0.11A。
- **数据手册建议**：输出 >12V 或输入 <2.5V 时，感值加大到 **22µH**。
- **前提是饱和电流要够**（Isat > 峰值电流），否则电感饱和直接失效。

### 5. ★★★ Boost（升压）拓扑的接线判据

| 元件 | 正确接法 |
|---|---|
| 电感 L | 一端接 **Vin**，另一端接 **SW 脚** |
| 二极管 D | **阳极接 SW**，**阴极接输出** ← 接反直接不工作 |
| 输出电容 | 输出对地 |
| 反馈分压 | 分压点接 **FB 脚** |
| EN 使能 | 接 IN（>1.5V 即使能） |
| NC 脚 | 悬空 |

### 6. ★★ 开关电源的电容：为什么必须低 ESR 陶瓷

- 数据手册要求输入/输出电容用**低 ESR 的 X5R/X7R 陶瓷，紧贴芯片引脚**。
- **铝电解在 1.2MHz 处阻抗已经很大**，起不到去耦作用，开关噪声会往母线跑。
- 输出电容**耐压要留 1.5~2 倍余量**（12V 输出 → 至少 25V，不要用 16V）。
- **折中做法**：电解上**并联一颗 0.1µF 陶瓷**压高频纹波。

### 7. ★★★ STM32F103C8T6 的三个硬约束

| 资源 | 容量 | 直接后果 |
|---|---|---|
| Flash | **64 KB** | 装不下字库、装不下 TCP/IP 全栈 |
| SRAM | **20 KB** | ★ 大数据（如 3 秒音频 96044 字节）**根本放不下**，必须分片流式处理 |
| 以太网 MAC | **无** | ★ lwIP + LAN8720 **这条路走不通**（只有 F107/F4/F7 才有 ETH） |

→ 要联网只能靠外挂模块（ESP8266 跑协议栈，MCU 发 AT 指令），**MCU 里不跑 TCP/IP**。

### 8. ★★★ 核心板 vs 底板 vs 模块：三个东西别混

| 名称 | 形态 | 能否拔下 |
|---|---|---|
| **核心板** | 独立小方板，40 针排针（BluePill 标准），只有 MCU + 晶振 + 复位 | ✅ **能插拔** |
| **底板** | 印丝印的大板（中控板/终端板），提供外设 | — |
| **模块** | 焊死在底板上的黑色金属壳（如 ESP-12E） | ❌ 焊死 |

**识别技巧**：看**能不能拔** + 看**上面有没有外设**。核心板光板一块，只有芯片。

### 9. ★★★ SWD（Serial Wire Debug）调试口：两根线就能下载 + 断点

- **SWD 只用 2 根信号线**：`SWDIO`（数据）+ `SWCLK`（时钟），对比 JTAG 省了 3 根。
- F103 上位置固定：**`PA13 = SWDIO`、`PA14 = SWCLK`**。
- **为什么核心板要单独引出这 4 针**：40 针排针里**根本没引 PA13/PA14**（PA12 之后直接跳 PA15），
  因为这两根脚一挂上排针就容易和外设打架 → 单独引一组最干净。
- 丝印对照：核心板 `DIO/CLK` ＝ 调试器 `SWDIO/SWCLK`，**同物异名**。

| 接线项 | 说明 |
|---|---|
| `GND` | **必接**，共地是通信的前提 |
| `DIO ↔ SWDIO` | 数据 |
| `CLK ↔ SWCLK` | 时钟 |
| `VCC ↔ 3V3` | **首选不接**，避免与板载电源对顶 |

### 10. ★★★ 串口 ISP（In-System Programming（在线编程））与 SWD 的取舍

| | 串口 ISP | SWD（J-Link/ST-Link） |
|---|---|---|
| 需要 | USB-TTL 或板载 CH340 | 专用调试器 |
| 下载 | ✅ | ✅ |
| **在线调试 / 断点** | ❌ **不行** | ✅ **可以** |
| 额外操作 | 每次要拨 BOOT0 + 按 RST | 一键 |

**结论**：只要能上 SWD 就上 SWD。**调 I2C 屏这种活儿，能打断点和不能打断点是两个难度。**

### 11. ★★★ 设备管理器"代码 28"＝ 驱动未安装

- 插上设备后 `其他设备` 里出现名字 + **黄色问号**，属性显示 **代码 28** → **不是硬件坏，是缺驱动**。
- 装完驱动后，条目会**移到对应分类下、问号消失**（如 USB 设备移到「通用串行总线控制器」）。
- ★ 判断"芯片活着"的线索：**设备名能正常显示出来**（说明固件在跑、USB 枚举成功），
  只剩驱动这一层没通。

### 12. ★★★ 调试器与目标板必须"共地"

- **两个 USB 都插同一台电脑** → 电脑 USB 口共地 → 天然满足。
- 用**手机充电头**给目标板供电 → 独立电源，**地与电脑不连通** → SWD 通信不稳甚至不通。
- ★ 同理：**同一时间只用一个电源**。插了 Type-C 就不要再接电池，否则两路电源对顶。

### 13. ★★ 开发板上的 Type-C 为什么不会烧芯片

- USB 标准就是 **5V 输入**，板上必然跟一颗 **LDO** 把它降到 3.3V。
- 验证方法：看 Type-C 口附近有没有一颗三脚稳压芯片（丝印 `1117` / `662K` / `ME6211` 等）。
- 本项目两块底板的供电链路：
  - **终端板**：`TP4056`（锂电充电）→ `MT3540`（升压 5V）→ `AMS1117`（LDO 3.3V）
  - **中控板**：Type-C 5V → `AMS1117` → 3.3V

### 14. ★★ 电源芯片按功能分三类（同一块板上会同时出现）

| 类型 | 干什么 | 典型器件 |
|---|---|---|
| 充电管理 | 给锂电池充电 | `TP4056` |
| 升压 Boost | 电池 3.7V → 5V | `MT3540` / `MT3608` |
| LDO 线性降压 | 5V → 3.3V | `AMS1117` / `HR1117` |

**升压和降压是两回事**：电池电压低于 5V 要先**升压**；升完再用 LDO 降到 3.3V。
★ 注意区分：`MT3608` 是升压，`HR1117` / `AMS1117` 是降压（都是 LDO）。

### 15. ★★ J-Link 与 J-Link OB 的区别

- **J-Link** = SEGGER 公司正品调试器（业界通用标准，比 ST-Link 兼容性更好）。
- **J-Link OB**（On Board）= **厂商授权给开发板厂商的板载精简版**，功能等价，价格低。丝印通常写 `J-LinkOB`。
- **★ 不要升级 OB 版固件**：它是授权版本，私刷固件可能变砖。提示升级一律选 `No`。

### 16. ★★ 读嘉立创 EDA `.eprj3` 工程的方法（不开 GUI 也能审图）

`.eprj3` 是**文件夹化工程**，本质是文本，可直接解析：

| 文件 | 内容 | 关键记录类型 |
|---|---|---|
| `*.esch2` | 原理图 | `COMPONENT` / `ATTR`(Designator, Pin Name, NET) / `WIRE` |
| `*.epcb2` | PCB | `PAD_NET`（焊盘网络）/ `STRING`（**丝印**） |

关键技巧：
- **★ PCB 的 `STRING` 丝印最有用**——能直接读出**接口面板上每个针脚印的是什么**，
  比从原理图连线去推断可靠得多（判断屏幕接口就是靠这个定下来的）。
- 解析注意：文件**末尾以 `|` 结尾**，`json.loads` 前要 `rstrip('|\n')`。
- 记录格式：`{"type":"XXX","ticket":N,"id":"..."}||{...}|`，**一条记录一行**。
- **元件绝对坐标 = `comp.pos + rot(引脚局部坐标, comp.rotation)`**，网络靠导线端点坐标匹配。

## 三、踩的坑

### 电路设计类

1. **升压整流管用了 1N4007**（自己画的坑） —— MT3608 是 1.2MHz 开关，1N4007 的 trr≈2µs 是开关周期的 2.4 倍，
   输出根本升不起来还会严重发热。**换 SS34（肖特基，40V/3A）后解决。**
   → 教训：**选二极管先看工作频率，别只看耐压和电流。**
2. **网络名塞进了说明文字**（自己画的坑） —— 写成 `+5V（外部提供）`，**全角括号进了真实网名**，
   违反命名规范、导出网表易出编码问题。应改成 `V5V0_EXT`，提示用 TEXT 注释单独写。
3. **两块独立电路的网络名不一致**（自己画的坑） —— 降压输出叫 `V-OUT-5V`、升压输入叫 `+5V`，
   两者在图上不连通。**是"串成一条链"还是"两道独立练习"必须先想清楚，不能两可。**

### 硬件认知类

4. **把"接口类型"和"模组形态"混为一谈** —— 看到 4 针 + SCK/SDA，就想当然地当成"标准 0.96" OLED 模块"，
   拆开看实物才发现是 **`V1.2` 转接板 + 30pin FPC**，屏玻璃直接贴板、背面无 IC（控制器在屏的 COG 上）。
   → **原理图只能定"是什么接口"，定不了"是什么模组"，后者必须看实物。**
5. **以为"中控板的 Type-C 能给 STM32 下载"** —— 查原理图才发现中控板的 `CH340K` 是接 **ESP-12E（WiFi）** 的
   （丝印 `WIFI_RXD/WIFI_TXD`），**根本没接 MCU**。给它下载得用底边 10P 排针或 SWD。
   → **同样是 Type-C，两块板的接法完全不同，别默认通用。**
6. **没第一时间认出 `J-Link OB`** —— 差点以为要另买 ST-Link。实际它功能完全等价，
   只是**丝印是 `SWDIO/SWCLK` 不是 `DIO/CLK`**，名字不同而已。
   → **认设备看丝印型号（`J-LinkOB`），别只看引脚名。**
7. **在 `Device>` 提示符下输 `s`** —— 那是接口选项不是设备名，靠 J-Link 用默认设备名兜底才歪打正着。
   → 正确顺序是 **`connect` → 设备名 → 接口(S) → 速度**。

# 10.8 笔记

## 一、干了什么

1. 在嘉立创 EDA 画了一个 **7.2V → 5V 的降压电路**原理图：LDO 用 **HR1117V-5.0**，输入、输出各挂一个 **10µF/25V 电解电容**。
2. 算清这颗 LDO 的功耗与结温，定出它到底能带多少电流。
3. 查清 7.2V 输入该选什么 **Buck（开关降压）** —— 先看的 MP2122A 不行，改看 MP2315 / TPS5430。
4. 试了嘉立创 EDA 自带的仿真功能，确认它验证不了 LDO。

---

## 二、知识点

### 1. ★★★ LDO 不是降压（Buck），两者功耗模型完全不同

| | LDO（线性稳压） | Buck（开关降压） |
|---|---|---|
| 原理 | 调整管"吃"掉多余电压 | 开关管 + 电感储能斩波 |
| 多余电压去向 | **全变成热** | 基本不发热 |
| 外围器件 | 只要两个电容 | 电感 + 续流二极管 + 电容 |
| 效率 | ≈ Vout/Vin（7.2→5V 只有 69%） | 85%~95% |
| 适用 | 小电流、压差小 | 大电流、压差大 |

**判据**：名字里带 **1117** 的（HR1117、AMS1117）**全是 LDO**。压差大 + 电流大 → 必须上 Buck。

### 2. ★★★ LDO 的功耗要自己扛：P = (Vin − Vout) × Iout

本项目的 LDO 是 **HR1117V-5.0**（立创 C54560849，SOT-89，Vin ≤ 15V，5V/1A 固定输出，dropout 1.1V@1A，静态电流 2mA；引脚 VIN=3 / VOUT=2 / GND=1）。

Vin=7.2V、Vout=5V → 压差 2.2V；SOT-89 的 θJA（结到环境热阻）≈100°C/W：

| 输出电流 | 耗散功率 | 温升 |
|---|---|---|
| 100 mA | 0.22 W | +22 °C |
| 200 mA | 0.44 W | +44 °C |
| 300 mA | 0.66 W | +66 °C |
| 500 mA | 1.10 W | +110 °C → 触热关断 |
| 1 A | 2.20 W | 直接烧 |

→ **这个封装的安全区只到 200 mA 左右**，超过 300 mA 就该换 Buck。

估算套路：先算 P，再乘 θJA 得温升，加上环境温度就是结温（一般芯片 Tj(max) = 125°C）。

### 3. ★★★ 选 Buck 先看 Vin 上限，不是只看电流

- ★ **MP2122A 的 Vin 上限只有 6V**，接 7.2V 会烧 —— 电流够大也没用。
- 7.2V 输入要选耐压覆盖得住的：**MP2315（4.5–24V / 3A，SOT23-8）**、**TPS5430（5.5 – 36V / 3A）**。
- 耐压要留余量：适配器空载时电压会往上飘。

### 4. ★★ 嘉立创 EDA 的仿真验证不了 LDO

- V3.2+ 有仿真功能（Simulide + NGspice 引擎，菜单「仿真」→「仿真设置」）。
- 但**不能导入第三方 .lib / .subckt 模型**，只有自带基础元件，**没有 1117 这类 LDO 模型**，**也不算温度/热**。
- → LDO 验证只能靠**手算 P = (Vin − Vout) × Iout** + 面包板实测；真要仿真就上 LTspice。

---

## 三、踩的坑

1. **嘴上说"降压"，选型时却按 Buck 的思路走** —— 实际画的是 LDO，两种电路的功耗模型完全不同，一开始没分清。
2. **以为能用 EDA 自带仿真验证这个 LDO** —— 没有 1117 模型、也不算温度，白试一圈。
3. **选 Buck 只看电流不看耐压** —— MP2122A 差点当 7.2V 输入的方案用，其实它 Vin 上限只有 6V。
4. **网标里用了 `-` 和 `.`** —— 写成 `V-IN-7.2V`，工具容易当分隔符切；规范写法是 `VIN_7V2`。
