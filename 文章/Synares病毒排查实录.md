# 潜伏三个月：一次 Synares 感染型病毒的排查、处置与复盘

> 一次真实的 Windows 主机应急响应记录。从"以为是网盘下载损坏"，到"确认是感染型病毒潜伏近三个月"，再到"全盘清除 + 被感染文档无损修复"。文中所有主机名、路径、账号信息均已脱敏。

---

## 一、事件概述

2026-10-10，我在给一台开发用 Windows 主机准备 STM32 工具链时，杀毒软件（火绒）报出 4 项告警，全部为 `Virus/Synares.a$SA`。顺藤摸瓜后发现：这不是 4 个孤立文件，而是一个**感染型病毒已经在本机潜伏约 3 个月**——它感染了数百个可执行文件、向 Excel 文档植入恶意宏，并通过注册表自启动持久化。更麻烦的是，当天老师通过 FTP 补发的开发工具包**又被同一病毒感染**，形成"清完即复发"的第二轮。

最终我们完成了定位源头、全盘清除、被感染文件无损修复、压缩包内病毒剔除，并恢复出全部开发工具链，**一个安装包都不需要重新下载**。

---

## 二、异常是怎么被发现的：一次误判与纠正

最初的现象看起来很像"下载损坏"：

- 老师发来的开发资料包里，有 **8 个完全不同的安装程序**（Keil、STM32CubeMX、ST-LINK 驱动、串口工具等）；
- 它们的**文件大小却精确相同**，全是 `638,180,864` 字节（约 608 MiB）；
- 多点采样 md5 一致，内容完全相同。我把其中一个双击运行，弹出的居然是 **VMware Workstation 安装程序**。

我第一反应是"百度网盘下载把文件串了"，甚至认为老师说的"被病毒感染了"不准确。**这是本次排查最大的一个错误判断。**

纠正发生在杀毒软件报警之后。当我用"内容判重 + 时间戳 + 数字对账"重新分析时，真相浮出水面：

- `638,180,864 − 637,409,472 = 771,392`，而桌面一个可疑文件 `~$cache1` 的大小是 `771,584`，两者只差一个 PE 头对齐的字节数；
- 三个不同名字的文件（`dpinst_x86.exe`、`STM32 ST-LINK Utility.exe`、`SetupSTM32CubeMX.exe`）的 md5、sha1 **完全相同**。

也就是说：**那个 608 MiB 的文件真身是一个被病毒顶替后的"病毒体 + 载荷"，被错误复制成了 8 个不同文件名。**老师是对的。

> 教训一：**多个不同程序的文件大小完全相同、内容一致，是高危信号，第一反应应该是查毒，而不是归因于网络传输问题。**

---

## 三、病毒身份：Synares 与它背后的 XRed 后门

杀软命名为 `Virus/Synares.a$SA`，属于**感染型病毒**（parasitic infector），不是那种独立运行的木马样本。联网查证后确认，它对应的是 **XRed 后门**（别名 Synaptics worm / DarkKomet）。

| 维度 | 详情 |
|---|---|
| 编写语言 | **Delphi**（PE 时间戳 `0x2a425e19` = 1992 年，系伪造） |
| 病毒体大小 | **637,409,472 字节**（约 607.9 MB） |
| 落脚路径 | `C:\ProgramData\Synaptics\Synaptics.exe` |
| 互斥体 | `Synaptics2X` |
| C2 服务器 | `xred.mooo.com`（备用 `freedns.afraid.org`） |
| 主要行为 | RAT 远控 / 键盘记录 / 信息窃取 / **U 盘蠕虫（autorun.inf）** / **向 .xlsm 植入宏** / 自启动持久化 |

它的核心感染机制很典型：

1. 把**原文件重命名**为 `._cache_原文件名.exe`（备份原件）；
2. 把自身（病毒体 + 约 771 KB 载荷）**写入原文件名顶替**；
3. 对 Excel 文档植入带下载器的宏。

**传播途径**：局域网传输工具、U 盘、聊天软件传文件——本质是"你信任谁，就从谁那里进来"。

## 四、证据链

判定结论靠的不是单一特征，而是多条独立线索互相印证。

| 证据 | 关键值 |
|---|---|
| 数字对账 | `638,180,864 = 637,409,472 + 771,392`；桌面 `~$cache1` = `771,584`（仅差 192 字节） |
| 时间戳聚类 | 三个文件同在 **2026-08-15 23:01~23:02** 被改写（批量感染特征） |
| 内嵌宏代码 | `.xlsm` 的 `xl/vbaProject.bin`（27,136 字节）内提取出 `WScript.Shell`、`ADODB.Stream`、`WinHttp.WinHttpRequest`、Google Docs / Dropbox 下载 URL、写 `\Synaptics\Synaptics.exe`、改注册表 `...\Excel\Security\VBAWarnings = 1` |
| WER 崩溃报告 | `C:\ProgramData\Microsoft\Windows\WER\ReportArchive\AppCrash_Synaptics.exe_*` 两份：**2026-07-16 21:58** 与 **2026-09-12 09:19**，异常码 `c0000005` |
| 火绒日志复核 | 报毒的 3 个文件 md5 完全相同（`a32c8938…`），"清除"后统一变为 637,409,472 字节的 VMware 安装包（官方 EV 签名 Valid） |

**攻击链还原**：恶意 Excel 宏从 Google Docs / Dropbox 下载 `Synaptics.rar` → 解出 `Synaptics.exe` 落到 `C:\ProgramData\Synaptics\` → `WScript.Shell` 执行 → 把 Excel 宏安全等级改成"启用所有宏" → 释放 `~$cache1` 载荷。

## 六、处置过程

### 阶段一：查证（只读取证，不执行可疑文件）

不运行任何可疑样本，纯靠**文件大小 / PE 结构 / 时间戳关联 / 数字对账 / 数字签名**判定。关键一步是解出火绒的 SQLite 日志（`C:\ProgramData\Huorong\...\log.db`，表 `HrLogV3_60`、`HrTrayMsg_60`）——注意**必须把 `-wal`/`-shm` 一起复制**，否则看不到最新记录。

### 阶段二：清除

交给杀毒软件"**清除**"而非手动删除。这是本次最重要的认知修正：感染型病毒的正确处置是"**摘掉病毒代码、还原原文件**"，手动删除等于**剥夺修复机会、永久丢失文件**（尤其是那些奖学金材料、加分证明等个人档案）。实证：`FeiQ.exe` 修复前 19,062,272 字节、含 4 个病毒标记；修复后 18,290,688 字节、标记全消失，差值 771,584 正是载荷大小。

### 阶段三：修复被宏感染的文档

火绒对文档层宏的清除不彻底。桌面 13 个 Excel 核查后，**7 个已清干净 / 6 个仍有恶意宏**（`vbaProject.bin` 27,136 字节 + `Workbook_Open`）。我做了精确摘宏，**技术要点是 .xlsm 摘宏必须改 4 处，只删 `vbaProject.bin` 不够**：

1. 删 `xl/vbaProject.bin`；
2. `[Content_Types].xml` 里删 vbaProject 相关的 `<Override>` **和** `<Default Extension="bin">`（两种写法都要处理）；
3. `[Content_Types].xml` 里把 `application/vnd.ms-excel.sheet.macroEnabled.main+xml` 改回 `...spreadsheetml.sheet.main+xml`；
4. `xl/_rels/workbook.xml.rels` 里删 vbaProject 的 `<Relationship>`。

处理前先**整目录备份原文件**，结果 6/6 字节一致、工作表/行数/单元格数全部无损。被感染的 `.xlsm` 原件改名加 `.quarantine` 后缀防误开。

### 阶段四：全盘复扫 + 压缩包内病毒剔除

杀软对**压缩包内部**的感染文件默认不动，所以旧病毒体还躺在包里。用工具逐包鉴定：

- `JLINK 驱动安装.zip >> Setup_JLink_V492.exe`：包内那份 22,892,544 = 干净版 22,120,808 **+ 771,736 载荷**，签名被抹 → **真病毒**；
- `SecureCRT.rar >> SecureCRT\lpk.dll`：46,592 字节 / 2019-05-26，而系统正版仅 12,288 字节 → **真木马**（HijackLPK）；
- `开发板相关的.zip >> Tftpd32.exe`：98,184 字节，PE 结构正常，内存字符串含作者名 `Ph. Jounin` → **误报**（下载的 TFTP 工具被标 HackTool）。

这里我一度认为"交给杀软处理压缩包会连里面的工具链一起没收"，**结果又是错的**：火绒**支持进包剔除毒文件后重新打包**。`JLINK 驱动安装.zip` 从 63,914,675 降到 63,505,015 字节（包内 exe 全部变回干净版），`开发板相关的.zip` 从 112,479,408 降到 104,369,849 字节（精准剔除了 `SecureCRT.zip`，66 MB 工具链完好无损）。

### 阶段五：收尾清理

杀软**没清注册表自启动项**，我手动处理：先 `reg export` 备份，再删除 `HKCU\...\Run` 下的 `Synaptics Pointing Device Driver`（指向 `C:\ProgramData\Synaptics\Synaptics.exe`）；确认为空目录后删除病毒据点 `C:\ProgramData\Synaptics\`;清空回收站；复查 `Winlogon` / `AppInit_DLLs` / 计划任务 / hosts / DNS 缓存，均干净。

**成果**：从压缩包原地恢复被替换的工具（如 27,700,527 字节的 ST-LINK Utility、5,279,232 字节的 PortHelper），并发现 `MDK\MDK533.EXE`（923 MB）是 **Arm Ltd 签名 Valid 的真货**，连同 ST 签名的 STM32CubeMX 6.2.0（301 MB），最终**一个安装包都不需要重新下载**。

## 七、关键经验教训

1. **多个不同名称文件大小完全相同 = 高危信号**。先按内容判重，别按文件名信任，第一反应查毒。
2. **感染型病毒要"清除"，不要直接删除**。杀软的"清除"能提取 PE 资源段还原原程序；手动删 = 永久丢失文件、剥夺修复机会。
3. **`._cache_` 前缀不能作为判据**。它是病毒"备份原件再顶替"的机制没错，但 JetBrains 的合法组件 `._cache_restarter.exe`（签名 Valid）也叫这名。**要靠特征字符串和数字签名区分。**
4. **`PADDINGXXPADDING` 尾部标记不是病毒特征**。对照实验：31,831 个正常 PE 中有 16 个带此标记，全是打印机驱动/资源 DLL——它其实是**资源编译器对纯资源文件的标准对齐填充**。我最初把它当铁证，是错的。
5. **压缩包内的病毒，杀软默认不动**。清完落地文件不等于清干净，包里那份还在。用 `bsdtar`（`C:\Windows\System32\tar.exe`）可以直接列/解 RAR，配 `--exclude` 精确剔除单个文件（本机没装 WinRAR/7-Zip 时尤其好用）。
6. **不要臆测杀软的处置粒度**。火绒能进包剔除病毒并重新打包，"点处理 = 整包没收"是我的臆测，实测工具链全部保住。
7. **数字签名比任何启发式判据都硬**。Valid 签名证明内容未被篡改，是判定"文件是否干净"最可靠的一把尺。
8. **溯源要覆盖全部入口**。我两次误判源头（先怪网盘、再怪文件传输工具），根因都是"只查了想当然的目录"。全盘按 ctime/mtime 排序找最早被感染的 PE，才是正解。
9. **潜伏可长达数月**。本次病毒 7 月中旬入驻，直到 10 月才被发现。定期全盘查杀、把实时监控扫描时机调到中/高，很有必要。

## 八、遗留事项与建议

- **重启后再跑一次全盘查杀**（杀软官方明确要求，防遗漏）；
- 翻查微信记录，找 **2026-07-13 前后发来 `FeiQ.exe` 的联系人**并通知对方查毒——对方很可能同样中毒，是传播链的上游；
- 用户确认新的 `.xlsx` 无误后，删除 `.quarantine` 文件与备份目录（**备份里是带宏的原文件，不要打开**）；
- 对搜狗输入法等在感染期被改动的软件，建议**官网重装**；
- **注册机（keygen）建议弃用**，杀软必报且本身风险高，改用官方免费授权社区版即可；
- 最彻底方案：若条件允许，重装系统。毕竟潜伏 3 个月，感染面难以完全穷尽。

> 一句话总结：这次真正的收获不是"抓到了病毒"，而是**学会了不要凭直觉下结论**——三次误判（网盘损坏、源头是传输工具、杀软会整包没收），每一次都被数据推翻。取证以文件系统的时间戳、大小、签名、哈希为准绳，才靠得住。
